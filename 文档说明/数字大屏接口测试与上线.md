# 数字大屏接口：测试方法与上线说明

本文档说明管理端「数字大屏」相关 **HTTP 接口**、**WebSocket 服务** 的联调测试方式，以及生产环境上线时的配置与运维要点。

---

## 1. 功能与入口一览

| 类型 | 说明 |
|------|------|
| HTTP | 需管理端登录 `token`（Header 或部分环境支持 `token` 参数，与现有后台一致） |
| 配置 | `config/visual_screen.php`（WS 监听地址、端口、路径说明） |
| 控制台 | `php think visual_screen_ws start` 启动独立 WS 进程（Workerman） |

### 1.1 HTTP 路径（多应用默认路由）

以下路径均位于 **management** 应用下，实际域名请替换为项目访问地址。

| 接口 | 方法 | 路径（示例） | 用途 |
|------|------|----------------|------|
| 全量快照 | GET/POST | `/management/visual_screen.visual_screen/getSnapshot` | 首屏全量数据，字段与 WS `visual_screen_snapshot` 的 payload 一致 |
| 销售趋势 | GET/POST | `/management/visual_screen.visual_screen/getSalesTrend` | 日/周/月趋势，与 WS `visual_screen_sales_trend_update` 对齐 |
| WS 说明 | GET/POST | `/management/visual_screen.visual_screen/getWsInfo` | 返回建议的 `wss` 地址、路径、端口提示（供前端拼接） |

### 1.2 WebSocket 协议摘要

- 连接 URL：`ws://<host>:<port>?token=<管理端token>`（生产一般为 `wss://` + 反向代理，见下文）
- 客户端消息外层：`event`、`ts`、`traceId`、`payload`（与产品协议文档一致）
- 支持事件：`visual_screen_subscribe`、`visual_screen_switch_region`、`visual_screen_switch_cycle`、`ping`

实现类：`app/command/VisualScreenWs.php`  
业务聚合：`app/management/service/VisualScreenService.php`

## 2. 测试方法

### 2.1 前置条件

1. 数据库、`.env` 中数据库配置可连通（订单、设备、地区等表与线上一致或测试库）。
2. 使用**管理端账号**登录，取得与现有接口相同的 **token**。
3. 若测 WS：本机或服务器已安装 PHP CLI，且可执行项目根目录下的 `think` 命令。

### 2.2 HTTP 接口测试（curl）

在 **Git Bash**、CMD 或 PowerShell 中执行（注意替换域名与 token）：

**全量快照（全国、日维度）**

```bash
curl -sS "https://你的域名/management/visual_screen.visual_screen/getSnapshot" \
  -H "token: 你的token" \
  -G \
  --data-urlencode "regionType=national" \
  --data-urlencode "regionName=" \
  --data-urlencode "cycle=day" \
  --data-urlencode "machinePage=1" \
  --data-urlencode "machinePageSize=20"
```

**省份视图**

```bash
curl -sS "https://你的域名/management/visual_screen.visual_screen/getSnapshot" \
  -H "token: 你的token" \
  -G \
  --data-urlencode "regionType=province" \
  --data-urlencode "regionName=广东" \
  --data-urlencode "cycle=week"
```

**销售趋势**

```bash
curl -sS "https://你的域名/management/visual_screen.visual_screen/getSalesTrend" \
  -H "token: 你的token" \
  -G \
  --data-urlencode "regionType=national" \
  --data-urlencode "cycle=month"
```

**WS 配置说明**

```bash
curl -sS "https://你的域名/management/visual_screen.visual_screen/getWsInfo" \
  -H "token: 你的token"
```

**期望结果**

- 业务成功时，返回体中 `state` 为 **200**（或与项目统一的成功码），`data` 内为 JSON 对象（含 `deviceOverview`、`tradeMetrics`、`salesTrend` 等）。
- 若 `state` 为 100、98 等，多为 **token 缺失/失效**，请先重新登录再测。

### 2.3 HTTP 接口测试（Postman / Apifox）

1. 新建请求，URL 填上述完整地址（GET 参数可在 Params 中填写）。
2. Headers 增加：`token` = 登录拿到的值。
3. 发送后检查响应 JSON 结构与前端大屏字段是否一致。

### 2.4 WebSocket 测试

#### 2.4.1 启动服务

在项目根目录（与 `think` 同级）执行：

```bash
php think visual_screen_ws start
```

默认监听见 `config/visual_screen.php`：`ws_host`、`ws_port`（默认端口 **2351**）。控制台出现 `Listening websocket://...` 即表示监听成功。

**说明（Windows）**：当前命令实现下，Windows 环境一般仅支持 **`start`**；`stop`/`restart` 等请在 Linux 部署机或使用进程管理工具结束 PHP 进程。

#### 2.4.2 使用浏览器控制台

1. 打开管理端页或任意页面，F12 打开控制台。
2. 将 `TOKEN` 替换为真实 token，`PORT` 为配置端口：

```javascript
const ws = new WebSocket('ws://127.0.0.1:PORT?token=TOKEN');
ws.onopen = () => {
  ws.send(JSON.stringify({
    event: 'visual_screen_subscribe',
    ts: Date.now(),
    traceId: 'test-1',
    payload: {
      regionType: 'national',
      regionName: '',
      cycle: 'day',
      machinePage: 1,
      machinePageSize: 128
    }
  }));
};
ws.onmessage = (e) => console.log(JSON.parse(e.data));
```

**期望**：首条业务消息为 `event === 'visual_screen_snapshot'`，`payload` 为大屏数据结构。

可继续发送 `visual_screen_switch_region`、`visual_screen_switch_cycle`、`ping` 验证切换与心跳。

#### 2.4.3 常见问题（WS）

| 现象 | 处理建议 |
|------|----------|
| 连接立即断开 | 检查 query 是否带 `token`；token 是否与后台加密盐一致、是否过期 |
| 连接被拒绝 | 确认本机防火墙、安全组放行 `ws_port`；确认进程已启动 |
| 无数据或全 0 | 账号数据权限、省份名称与 `earth_states` 是否匹配；测试库是否有订单/设备数据 |

## 3. 上线方法

### 3.1 代码与配置发布

1. 将包含 `app/management/controller/visual_screen`、`app/management/service/VisualScreenService.php`、`app/command/VisualScreenWs.php`、`config/visual_screen.php`、`config/console.php` 等改动的版本发布到服务器。
2. 执行 Composer 安装（若服务器流程包含）：保证 `workerman/workerman` 等依赖与线上一致。
3. 在服务器 `.env` 或环境变量中配置（可选）：

```ini
# 可选，不配则使用 config/visual_screen.php 默认值
VISUAL_SCREEN.WS_HOST=0.0.0.0
VISUAL_SCREEN.WS_PORT=2351
VISUAL_SCREEN.WS_PATH=/ws/visual-screen
```

若项目未使用 `env()` 解析上述键名，可直接改 `config/visual_screen.php` 中的 `env('visual_screen.xxx')` 对应默认值或通过部署脚本替换配置文件。

### 3.2 Nginx 反向代理（推荐：对外 `wss`，对内转发到 Workerman）

前端页面为 **HTTPS** 时，浏览器要求 WebSocket 使用 **wss**。常见做法：Nginx 监听 443，将路径（如 `/ws/visual-screen`）反代到本机 `127.0.0.1:2351`。

示例（需按实际域名、证书路径调整）：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl;
    server_name your.domain.com;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location /ws/visual-screen {
        proxy_pass http://127.0.0.1:2351;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

前端连接示例：

```text
wss://your.domain.com/ws/visual-screen?token=<登录token>
```

**注意**：Workerman 侧监听的是 **裸 WebSocket**，与 Nginx `location` 路径是否一致取决于前端实际连接 URL；若 Workerman 仅监听端口、不带路径，则 `proxy_pass` 到端口即可，由 Nginx 统一路径。

### 3.3 进程守护（生产必做）

`php think visual_screen_ws start` 默认以前台方式运行，掉线即停。**生产环境**请使用 **Supervisor**、**systemd** 或现有发布平台守护进程，例如 Supervisor 片段：

```ini
[program:visual_screen_ws]
directory=/www/wwwroot/your_project
command=/usr/bin/php think visual_screen_ws start
autostart=true
autorestart=true
user=www
stdout_logfile=/www/wwwroot/your_project/runtime/visual_screen_ws.log
stderr_logfile=/www/wwwroot/your_project/runtime/visual_screen_ws_err.log
```

按需修改 `directory`、`command` 中 PHP 路径与项目路径。

### 3.4 安全与运维

1. **Token**：与现有管理端一致，仅走 HTTPS/WSS，避免在日志中打印完整 token。
2. **防火墙**：仅对 Nginx 或内网开放 WS 端口，不对公网裸暴露 Workerman 端口（若已用 Nginx 反代，可只监听 `127.0.0.1:2351`）。
3. **资源**：大屏聚合查询较重，注意 MySQL 索引与监控；必要时对 HTTP 快照接口做限流或缓存（按业务评估）。
4. **扩容**：单进程 Workerman 有上限；高并发时需多机、多端口或引入网关方案（按架构评审执行）。

### 3.5 上线检查清单（建议）

- [ ] HTTP `getSnapshot` / `getSalesTrend` / `getWsInfo` 在预发环境用真实 token 验证通过  
- [ ] WS 进程由守护拉起，重启服务器后自动恢复  
- [ ] Nginx `wss` 与超时、Upgrade 头配置已验证  
- [ ] `deviceOverview` 与库表 `is_operating`（在营/在库）口径与运营确认一致  
- [ ] 大屏前端已切换为真实接口地址（或按环境变量区分 mock/生产）
