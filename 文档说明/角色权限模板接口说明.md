# 角色权限模板

## 业务规则

- 新版模板按顶级导航保存 `data_scope` 和增删改查独立权限，并递归生成最终节点集合。
- `d_type` 仅保留给历史角色权限兼容，新版模板接口不再提交。
- 一个角色最多关联一个模板，通过 `auth_role.template_id` 保存。
- 每个账号通过 `auth_manager.use_role_template` 决定权限来源：`1` 使用模板，`2` 走历史逻辑。
- 字段默认值为 `2`，数据库上线后所有历史账号行为保持不变。
- 开启模板的账号：已关联模板的角色读取模板节点，未关联模板的角色继续读取历史角色节点。
- 关闭模板的账号：全部读取历史 `auth_role_node`，模板维护不会覆盖历史节点。
- 角色模板和历史角色节点可分别维护，便于同一角色下账号灰度切换。

## 接口

| 接口 | 参数 | 说明 |
| --- | --- | --- |
| `/management/auth.auth_role_template/getList` | `name,status,pageNum` | 查询模板列表 |
| `/management/auth.auth_role_template/getFind` | `art_id` | 查询模板 |
| `/management/auth.auth_role_template/add` | `name,desc,status` | 新增模板 |
| `/management/auth.auth_role_template/update` | `art_id,name,desc,status` | 修改模板 |
| `/management/auth.auth_role_template/del` | `art_id` | 删除未使用模板 |
| `/management/auth.auth_role_template/getNodes` | `art_id` | 查询模板节点 |
| `/management/auth.auth_role_template/saveNodes` | `art_id,nodeList` | 覆盖保存模板节点 |
| `/management/auth.auth_role_template/getTopNavigationNodes` | `art_id`（可选） | 查询权限树；传模板ID时返回顶级和子导航的当前设置 |
| `/management/auth.auth_role_template/saveTopNavigationNodes` | `art_id,top_navigation_list` | 按顶级默认配置递归展开，并支持子导航覆盖保存 |
| `/management/auth.auth_role_template/apply` | `art_id,role_id` | 关联模板到角色 |
| `/management/auth.auth_manager_role/setRoleManagers` | `role_id,manager_ids` | 替换设置某角色的账号集合，空数组表示清空 |

账号新增/修改接口支持 `use_role_template`，取值 `1`（使用模板）或 `2`（历史逻辑）。

`saveNodes` 请求示例：

```json
{
  "art_id": 1,
  "nodeList": {
    "101": 1,
    "102": 2,
    "103": 3
  }
}
```

`setRoleManagers` 请求示例：

```json
{
  "role_id": 10,
  "manager_ids": [101, 102, 103]
}
```

`saveTopNavigationNodes` 请求示例：

```json
{
  "art_id": 1,
  "top_navigation_list": [
    {
      "node_id": 69,
      "data_scope": "all",
      "create_enabled": 1,
      "delete_enabled": 1,
      "update_enabled": 1,
      "query_enabled": 1,
      "children": [
        {
          "node_id": 72,
          "create_enabled": 1,
          "delete_enabled": 1,
          "update_enabled": 1,
          "query_enabled": 1
        },
        {
          "node_id": 73,
          "create_enabled": 0,
          "delete_enabled": 0,
          "update_enabled": 0,
          "query_enabled": 1
        }
      ]
    }
  ]
}
```

- `data_scope` 默认按 `organization` 保存，查询接口限制为账号所属组织数据。
- 只有明确传 `data_scope=all` 时，查询接口才不增加组织范围限制。
- `create_enabled/delete_enabled/update_enabled/query_enabled` 分别展开对应 `permission_action` 节点；`query_enabled=1` 时同时授权 `permission_action=export` 的导出节点。
- 每个顶级导航至少选择一种接口权限。
- 顶级导航配置作为默认值，`children` 里只提交需要差异化覆盖的子导航。
- 子导航未传 `data_scope` 或某个权限开关时，默认继承父导航配置。
- 子导航覆盖会先清空该子树从父导航继承的权限，再按自己的配置重新展开，避免“只查”场景残留新增、删除、修改权限。
- 查询接口会在每个存在显式配置的节点上返回 `template_setting`，前端可据此回显顶级默认配置和子导航覆盖配置。
- 保存采用覆盖模式，不写入或覆盖历史 `auth_role_node`。
