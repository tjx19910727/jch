# 设备端客户退货日志接口

## 业务边界

- 本接口仅校验订单并记录客户退货日志，不修改订单状态、不创建退款单、不触发资金退款。
- 普通四位编码用于匹配当前设备 `sale_orders.trade_no` 的后四位。
- 手机号仅作为客户退货日志信息记录，不参与订单匹配。
- 特殊编码匹配成功时跳过订单校验，日志中的 `order_id` 为 `0`、`trade_no` 为空。
- 普通编码未匹配订单时仍记录失败日志，并返回校验失败。

## 数据表

表名：`machine_refund_goods_log`

建表语句已追加至 `数据库更新.sql` 的 `#20260611` 段。

关键状态：

- `verify_type=1`：订单号后四位校验
- `verify_type=2`：特殊编码跳过订单校验
- `verify_status=1`：校验成功
- `verify_status=2`：校验失败

## 特殊编码配置

特殊编码必须为四位数字，默认留空并禁用：

```ini
[REFUND_GOODS]
SPECIAL_CODE = 需要配置的四位数字
```

代码配置位置：`config/refund_goods.php`

## 接口

请求地址：

```text
POST /machine/receive/submitRefundGoodsLog
```

请求参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `msg_id` | 是 | 唯一消息ID |
| `machine_id` | 是 | 设备编号 |
| `timestamp` | 是 | 时间戳 |
| `sign` | 是 | 设备签名 |
| `mobile` | 是 | 客户手机号，最长32字符 |
| `input_code` | 是 | 用户输入的四位数字编码 |
| `pic_out_goods_box` | 是 | 出料箱图片地址 |
| `video_out_goods_box` | 是 | 出料箱视频地址 |
| `video_refund_goods` | 是 | 全局退货视频地址 |

成功响应数据：

```json
{
  "mrgl_id": 1,
  "verify_type": 1,
  "verify_status": 1,
  "order_id": 123,
  "trade_no": "2026061112345678"
}
```

普通编码无法匹配当前设备订单时返回失败，但 `mrgl_id` 仍为已保存的失败日志ID。
