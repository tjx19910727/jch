# 新分账联调自检清单

> 2026-06-10 最终调整：`revenue_payee_config` 已删除。渠道开关检查 `revenue_pay_channel`；普通分账账户检查设备绑定的 `rule_mode=1` 规则明细；结算周期检查实际命中的 `revenue_rule.settlement_type/settlement_days`。下文仍出现的收款策略新分账配置步骤属于调整前记录。

## 0. 收款与新分账边界

- 原收款业务继续使用 `strategy_payee/sp_id` 确定收款策略。
- 新分账允许只读订单最终确定的 `sp_id`，并只读 `strategy_payee.payee_type/ao_id` 作为分账判断输入。
- 新分账配置必须通过 `/management/revenue.revenue_payee_config/*` 独立维护。
- 收款策略新增、修改、删除接口不得写入 `revenue_*` 表。
- 新分账模块不得新增、修改、删除 `strategy_payee` 数据，不得修改其表结构。
- 新分账计算结果只写入 `revenue_order` 等 `revenue_*` 新表。

## 1. 数据配置检查

### 1.1 分账渠道

检查表：`revenue_pay_channel`

必须至少配置一条启用渠道，否则支付不会生成 `revenue_order`。

示例：

```sql
SELECT * FROM revenue_pay_channel WHERE status = 1;
```

预期：

- 本次测试订单的 `pay_type` 或收款策略 `payee_type` 能命中启用配置。
- `revenue_pay_channel` 只控制哪些支付渠道触发新分账，不保存结算周期。
- `revenue_payee_config` 即时分账配置为 `settlement_type=1`、`settlement_days=0`。
- `revenue_payee_config` T+1 分账配置为 `settlement_type=2`、`settlement_days=1`。

### 1.2 分账账户

检查表：`revenue_account`

普通分账、设备出租、设备分账涉及的接收组织都必须有启用账户。

```sql
SELECT * FROM revenue_account WHERE status = 1;
```

预期：

- 收款组织 A 有默认分账账户。
- 商品组织 B 有分账账户。
- 设备分账策略中的 B/C 组织均有分账账户。
- 更新分账账户时，即使只提交 `ao_id` 或只提交 `manager_id`，也必须保证最终管理人所属组织与账户组织一致。
- 已被 `revenue_rule_item` 引用的分账账户，不允许修改 `ao_id` 或 `manager_id`；应新建账户并调整规则明细。
- 当前管理人被停用后，仍允许修改账户名称或停用账户；更换管理人或重新启用账户时，新管理人必须启用。

### 1.3 收款策略新分账配置

检查表：`revenue_payee_config`

```sql
SELECT * FROM revenue_payee_config WHERE sp_id = {收款策略ID} AND status = 1;
```

预期：

- `enable_revenue=1`
- `default_ra_id` 有值
- `default_manager_id` 与 `revenue_account.manager_id` 一致

如果 `enable_revenue=2`，该收款策略不会生成新分账。

## 2. 策略配置检查

### 2.1 普通分账

无需额外 `revenue_rule`。

条件：

- 订单商品组织均等于收款组织。
- 设备未绑定设备分账策略。
- 收款渠道和收款策略均启用新分账。

预期：

- 生成 `rule_mode=1`
- `source=normal`
- `income_amount=订单金额`

### 2.2 设备出租分账

检查：

```sql
SELECT rr.*, rri.*
FROM revenue_rule rr
JOIN revenue_rule_item rri ON rri.rr_id = rr.rr_id
WHERE rr.rule_mode = 2 AND rr.status = 1 AND rri.status = 1;
```

预期：

- 设备绑定 `rule_mode=2` 策略。
- B 商品组织对应一条 `receiver_ao_id=B组织ID` 的策略明细。
- `calc_type=1`，`calc_value` 可为 `100` 或其他比例。

### 2.3 设备分账

检查：

```sql
SELECT rr.*, rri.*
FROM revenue_rule rr
JOIN revenue_rule_item rri ON rri.rr_id = rr.rr_id
WHERE rr.rule_mode = 3 AND rr.status = 1 AND rri.status = 1;
```

预期：

- 设备绑定 `rule_mode=3` 策略。
- B/C 等分账接收组织有对应策略明细。
- 固定比例合计不超过 100%。

## 3. 支付生成自检

支付前调用新逻辑后检查：

```sql
SELECT *
FROM revenue_order
WHERE order_id = {订单ID}
ORDER BY ro_id ASC;
```

### 3.1 渠道未启用

条件：

- `revenue_pay_channel` 未配置该订单支付渠道。

预期：

- 支付继续。
- 不生成 `revenue_order`。

### 3.2 收款策略关闭分账

条件：

- `revenue_payee_config.enable_revenue=2`

预期：

- 支付继续。
- 不生成 `revenue_order`。

### 3.3 普通分账

预期：

- `rule_mode=1`
- `source=normal`
- `receiver_ao_id=订单收款组织`
- `manager_id=默认分账账户管理人`

### 3.4 设备出租 100%

条件：

- A 设备销售 B 商品。
- B 出租策略比例为 100%。

预期：

- `rule_mode=2`
- `source=rental`
- `receiver_ao_id=B组织ID`
- `income_value=100`
- `income_amount=该 B 商品子订单金额`

### 3.5 设备出租非 100%

条件：

- A 设备销售 B 商品。
- B 出租策略比例为 80%。

预期：

- `income_value=80`
- `income_amount=B商品子订单金额 * 80%`

### 3.6 设备分账

条件：

- 设备绑定 B 20%、C 30%。

预期：

- B 生成一条 `income_value=20`
- C 生成一条 `income_value=30`
- 若策略 `base_type=2`，设备分账基数应扣除出租已分账金额。

## 4. 支付成功结算自检

支付成功后检查：

```sql
SELECT ro_id, status, income_amount, refund_amount, revenue_time
FROM revenue_order
WHERE order_id = {订单ID};
```

预期：

- `status=1`
- `revenue_time` 有值
- `account_type=balance` 的账户管理人余额增加 `income_amount - refund_amount`
- 重复回调不重复增加余额

T+N 渠道支付成功后的预期：

- `status=2`
- `planned_revenue_time` 为支付日零点加 N 天
- 到期执行 `php think time_task revenue settleDue` 后变为 `status=1`
- 生产环境建议每分钟执行一次 `php think time_task revenue settleDue`

### 4.1 测试环境模拟支付成功

接口：`/management/revenue.revenue_order/mockPaySuccess`

限制：

- 仅 `env('CglPay.is_test')` 为 true 时允许调用。

入参：

- 必填：`trade_no` 或 `order_id`
- 可选：`pay_type`、`pay_method`、`sp_id`、`mch_no`、`out_trade_no`、`pay_time`

行为：

- 若订单尚未生成新分账单，先执行新分账预计算。
- 只结算 `status=0/2` 的新分账单。
- 将订单置为 `pay_status=3`。
- 不触发真实支付、不触发完整出货/MQ/通知，仅用于新分账联调。

## 5. 退款自检

退款成功后检查：

```sql
SELECT ro_id, income_amount, refund_amount
FROM revenue_order
WHERE order_id = {订单ID};
```

预期：

- `refund_amount` 增加。
- 余额型账户已结算时，对应账户管理人余额扣减。
- 部分退款不超过该分账记录可退金额。
- 全额退款后 `refund_amount` 不超过 `income_amount`。

## 6. 后台查询自检

接口：

- `/management/revenue.revenue_order/getList`
- `/management/revenue.revenue_order/getFind`

常用筛选：

- `order_id`
- `trade_no`
- `sp_id`
- `rule_mode`
- `source`
- `status`
- `payer_ao_id`
- `receiver_ao_id`
- `manager_id`
- `ra_id`
- `machine_id`
- `period_key`
- `create_time=2026-06-01~2026-06-30`
- `revenue_time=2026-06-01~2026-06-30`

权限预期：

- 普通账户管理人只能看到 `manager_id=当前登录账号` 的记录。
- 审核权限账号可看更大范围。

组织名称返回约定：

- revenue 后台查询接口返回 `ao_id` 时，同时返回 `organization_name`。
- 返回 `payer_ao_id` 时，同时返回 `payer_organization_name`。
- 返回 `receiver_ao_id` 时，同时返回 `receiver_organization_name`。
- 以上约定适用于列表、单条详情、规则明细、设备绑定、嵌套 `revenue_orders` 和模拟支付结果。
- 组织不存在或组织ID为空时，对应组织名称返回空字符串。

支付类型说明返回约定：

- 新分账后台接口返回 `pay_type` 时，同时在同级返回 `pay_type_desc`。
- `pay_type_desc` 按 `config/payment.php` 中的 `pay_type_map` 生成。
- 未配置的支付类型返回 `支付类型#{pay_type}`，用于识别配置遗漏。
- 当前适用于分账支付通道列表/详情、分账订单查询接口，以及分账订单详情和模拟支付结果中嵌套的 `sale_order`。

## 7. 异常场景

### 7.1 渠道启用但未配置收款策略新分账配置

预期：

- 支付继续。
- 不生成 `revenue_order`。
- 该收款策略只有通过 `revenue_payee_config` 明确启用后才参与新分账。
- 后台配置自检可将其列为候选策略，但不得计入 `has_error=true`。

### 7.2 A 设备销售 B 商品但未配置出租策略

预期：

- 支付前失败。
- 错误提示：设备出租分账策略未配置。

### 7.3 B 商品组织未配置出租比例

预期：

- 支付前失败。
- 错误提示：商品组织未配置设备出租分账比例。

### 7.4 分账总额超过订单金额

预期：

- 支付前失败。
- 错误提示：分账总额不能超过订单金额。

### 7.5 已结算订单重复重算

预期：

- 不允许覆盖。
- 错误提示：订单已存在非待支付分账记录，不允许重算。
