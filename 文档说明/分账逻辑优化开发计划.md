# 分账逻辑优化开发计划

> 重要更新：本计划中的“扩展或修改 `strategy_payee`”属于早期方案，现已废弃。最终实现不得修改旧收款策略表、数据和保存流程；`strategy_payee/sp_id` 仅作为实际收款结果输入，新分账配置统一存储于 `revenue_*` 新表。最终边界以《新分账功能变动与影响审计》为准。

## 1. 开发目标

完成普通分账、设备出租分账、设备固定比例分账、设备阶梯分账四类能力，并保证所有分账订单都能在账户管理人后台查询。

本次开发以全新的 `revenue_order` 作为订单分账结果的统一权威表，新增策略配置表承载新规则。旧分账逻辑弃用，新需求不复用旧分账策略表和旧分账结果表。

## 2. 版本拆分

### V1：配置与计算闭环

目标：先让新分账规则能配置、能生成分账记录、能结算。

范围：

- 分账账户管理。
- 收款策略强制绑定分账账户及账户管理人。
- 设备出租分账。
- 设备固定比例分账。
- 设备阶梯分账，按设备自然月累计营业额命中比例。
- 新分账结算。

### V2：后台查询与运营能力

目标：账户管理人可查、可筛选、可导出分账订单。

范围：

- 分账订单列表。
- 分账订单详情。
- 分账导出。
- 仅展示新分账订单。
- 权限过滤完善。

### V3：增强能力

目标：处理复杂财务场景。

范围：

- 跨阶梯订单拆分计算。
- 退款后阶梯营业额重算或调整。
- 第三方支付平台真实分账接口。
- 分账对账、提现、财务报表。

## 3. 数据库开发计划

### 3.1 新增表

新增 `revenue_account`：

- 管理分账账户。
- 绑定账户所属组织。
- 绑定账户管理人。
- 保存账户展示账号。

新增 `revenue_rule`：

- 分账策略组。
- 区分普通、设备出租、设备分账。

新增 `revenue_rule_item`：

- 分账策略明细。
- 每条记录对应一个接收组织、分账账户和账户管理人。
- 支持百分比、固定金额、全额、阶梯百分比。

新增 `revenue_rule_item_tier`：

- 阶梯分账区间。
- 保存营业额下限、上限、对应分账比例。

新增 `revenue_rule_machine`：

- 设备绑定分账策略组。

### 3.2 扩展表

扩展 `strategy_payee`：

- `default_ra_id`：默认分账账户。
- `default_manager_id`：默认账户管理人。

新增 `revenue_order`：

- `rule_mode`：分账模式。
- `rr_id`、`rri_id`、`rrit_id`：策略和阶梯命中信息。
- `payer_ao_id`：收款/代收组织。
- `receiver_ao_id`：分账接收组织。
- `ra_id`：分账账户。
- `manager_name`、`account_type`、`account`：历史快照。
- `source`：normal、rental、device_rule、tier。
- `period_key`、`period_amount_before`、`period_amount_after`：阶梯统计快照。

### 3.3 迁移脚本

任务：

- 从 `auth_manager.bill_account` 初始化 `revenue_account`。
- 为已有 `strategy_payee` 尝试补齐默认分账账户。
- 不迁移旧分账订单。
- 统一使用 `sale_orders_details.sod_ao_id` 作为商品组织字段口径。

验收：

- 迁移脚本可重复执行。
- 历史分账记录不丢失。
- 新字段为空时旧订单仍可正常查询。

## 4. 后端开发计划

### 4.1 分账账户模块

新增模型：

- `RevenueAccountModel`

新增 Trait/Client：

- `RevenueAccountTrait`
- `RevenueAccountClient`

新增接口：

- `add`
- `update`
- `getList`
- `getFind`
- `disable`

校验：

- `ao_id` 必填。
- `manager_id` 必填且账号有效。
- 同一组织下默认账户规则需明确。
- 停用账户前检查是否被启用策略引用。

### 4.2 收款策略改造

涉及文件：

- `app/management/controller/strategy/StrategyPayee.php`
- `app/AppFactory/Management/Strategy/StrategyPayeeClient.php`
- `app/AppFactory/Kernel/Traits/Strategy/StrategyPayeeTrait.php`
- `app/AppFactory/Kernel/Model/Strategy/StrategyPayeeModel.php`
- `app/management/validate/VStrategyPayee.php`

任务：

- 新增收款策略时要求绑定 `default_ra_id`。
- 校验分账账户所属组织与收款策略 `ao_id` 一致。
- 保存 `default_manager_id`。
- 列表和详情返回默认分账账户、账户管理人信息。

验收：

- 未配置分账账户不能保存收款策略。
- 绑定停用账户不能保存。
- 旧收款策略仍可查询。

### 4.3 分账策略模块

新增模型：

- `RevenueRuleModel`
- `RevenueRuleItemModel`
- `RevenueRuleItemTierModel`
- `RevenueRuleMachineModel`

新增接口：

- 策略组新增、修改、列表、详情、停用。
- 策略明细新增、修改、删除。
- 阶梯区间新增、修改、删除。
- 设备绑定、解绑策略组。

校验：

- 固定比例策略合计不能超过 100%。
- 阶梯策略同一账户区间不能重叠。
- 阶梯区间必须满足 `threshold_min < threshold_max`。
- 任一营业额阶段下，策略组合计比例不能超过 100%。
- 每个策略明细必须绑定有效分账账户和账户管理人。

### 4.4 分账计算服务

建议新增服务：

- `app/AppFactory/Kernel/Service/Revenue/RevenueCalculator.php`

职责：

- 读取订单和订单明细。
- 判断分账模式。
- 计算普通分账。
- 计算设备出租分账。
- 计算设备固定比例分账。
- 计算设备阶梯分账。
- 生成 `revenue_order` 数据。

关键方法建议：

- `calculate(array $order): array`
- `calculateNormal(array $order): array`
- `calculateRental(array $order, array $details): array`
- `calculateDeviceRule(array $order, array $details): array`
- `calculateTierItem(array $order, array $ruleItem): array`
- `getMachineMonthlyTurnover(int $mId, string $periodKey): string`
- `createRevenueRecords(array $records): bool`

接入点：

- `BeforeOrderPaymentTrait::countIncome()`
- `AppFactory\Api\V2\V2Client`
- `AppFactory\Machine\Receive\ActivityClient`
- 其他调用旧 `countIncome()` 或 `addRevenue()` 的入口。

幂等要求：

- 同一订单重复调用时，不重复生成分账记录。
- 建议生成前检查 `revenue_order` 是否已有该订单新分账记录。
- 支付失败或撤销时保留还是删除分账记录需确认；建议保留并标记状态。

### 4.5 阶梯分账计算

默认算法：

- 周期：自然月。
- 统计维度：设备 `m_id`。
- 营业额：支付成功订单金额减成功退款金额。
- 命中方式：按本单后累计营业额整体命中阶梯。

示例：

- 本单前设备当月营业额 4800。
- 当前订单分账基数 300。
- 本单后累计 5100。
- A 账户命中 `>=5000` 阶梯，按 25% 计算整单分账。

记录快照：

- `period_key=2026-06`
- `period_amount_before=4800`
- `period_amount_after=5100`
- `rrit_id=命中的阶梯ID`
- `income_value=25`

### 4.6 结算改造

涉及文件：

- `app/AppFactory/Kernel/Traits/Payment/AfterOrderPaymentTrait.php`

任务：

- `settlementRevenue()` 支持新字段。
- 余额型账户继续增加 `auth_manager.balance`。
- 非余额型账户先只更新分账状态，不做真实打款。
- 使用 `income_amount - refund_amount` 作为可结算金额。
- 保持已结算记录幂等。

验收：

- 支付成功后分账状态正确。
- 重复回调不重复入账。
- 退款后可结算金额正确。

## 6. 测试计划

### 6.1 配置测试

- 收款策略未绑定分账账户，保存失败。
- 分账账户停用后不能绑定新策略。
- 固定比例合计超过 100%，保存失败。
- 阶梯区间重叠，保存失败。
- 阶梯比例组合在任一阶段超过 100%，保存失败。

### 6.2 订单分账测试

- 普通分账：A 设备销售 A 商品，生成 A 分账记录。
- 设备出租：A 设备销售 B 商品，B 获得该商品金额。
- 固定比例设备分账：B 20%、C 30%，分别生成记录。
- 阶梯分账：低于 5000、达到 5000、超过 8000 三组订单分别验证比例。
- 混合订单：A 商品 + B 商品 + 设备分账策略。

### 6.3 支付结算测试

- 支付成功后分账状态更新。
- 支付失败不入账。
- 重复支付回调不重复增加余额。
- 退款后分账退款金额正确。

### 6.4 权限测试

- A 账户管理人只能看 A 管理的分账订单。
- B 账户管理人只能看 B 管理的分账订单。
- 审核权限账号可看授权范围数据。
- 普通组织账号不能越权查看其他组织数据。

## 8. 上线计划

### 8.1 上线前

- 确认现网 `sale_orders_details.sod_ao_id` 字段。
- 备份分账相关表。
- 执行迁移脚本预演。
- 准备回滚 SQL。
- 准备测试设备和测试组织。

### 8.2 上线顺序

1. 上线数据库结构。
2. 上线后端新分账代码，旧分账入口不再参与本需求计算。
3. 执行数据初始化脚本。
4. 上线后台配置页面。
5. 给测试设备配置新分账策略。
6. 灰度验证订单支付、分账生成、结算、查询。
7. 逐步切换更多设备。

### 8.3 回滚策略

- 新表与旧分账表隔离，旧分账数据不进入新分账后台。
- `strategy_payee` 新增字段为空时，新收款策略不允许保存。
- `revenue_order` 只记录本需求产生的新分账订单。
- 若新分账计算异常，通过配置开关暂停新分账生成，不回退到旧分账逻辑。

## 9. 待确认事项

1. 设备出租分账和设备分账是否同时执行。
2. 设备分账基数是否扣除出租商品金额。
3. 阶梯营业额使用支付金额还是净营业额。
4. 阶梯命中按本单后累计整体计算，还是跨阶梯拆分。
5. 退款后是否影响当月阶梯累计营业额。
6. 非余额型分账账户本期是否只记录，不真实打款。
7. 普通分账是否必须生成分账记录；建议生成。
